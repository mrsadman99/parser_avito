# Веб-приложение

Интерфейс находится в `web-server/` (React + Vite), API — в `server/`
(FastAPI), пользователи и подписки — в `storage/web.db`, результаты —
в `database.db`. Парсер читает подписки независимо от процесса API.

## Подписки

Создание и изменение через `/api/links` проверяют HTTP(S)-адрес на домене
`avito.ru` или его поддомене, неотрицательные цены и порядок границ,
дату в формате `YYYY-MM-DD`. Ключевые слова очищаются от пробелов и дублей.

## Сессии

`POST /api/login` и `POST /api/register` возвращают bearer-токен.
`GET /api/me` возвращает текущего пользователя и признак администратора.
`POST /api/logout` отзывает только переданный токен; повторный выход безопасен.

Каждый вход создаёт отдельную сессию на 30 дней. Сессии пользователей
и администратора хранятся в SQLite и доступны всем процессам API.
В базе сохраняются только хеши токенов. Изменение пароля администратора
в конфигурации и перезапуск API делают его прежние сессии недействительными.

При первом запуске старые пользовательские токены автоматически переносятся
в таблицу сессий на 30 дней и удаляются из `users.token`. Старые сессии
администратора, существовавшие только в памяти, требуют повторного входа.

## Выдача объявлений

`GET /api/ads/page?link_id=123&page=1&page_size=50` возвращает
`{items, total, page, page_size}`. `page_size` ограничен 200 строками;
если страница исчезла после обновления данных, возвращается последняя доступная.
`total` — число результатов после фильтрации.

Параметры: `delivery_only`, `city` (подстрока без учёта регистра, включая кириллицу),
`published_from` и `published_to` (включительные границы в Unix-миллисекундах),
`sort` (`price`, `scanned_at`, `refreshed_at`, `sort_time`, `seller_reviews`,
`seller_rating`, `has_delivery`, `city`), `direction` (`asc`/`desc`).
Фильтрация, подсчёт и сортировка выполняются в SQLite. Порядок при одинаковых
значениях стабилен по ID, цене и ключу подписки. Пустые значения сортируются
по правилам SQLite: первыми при возрастании, последними при убывании.

Вместо `link_id` можно передать `url`: обычному пользователю доступны только
его подписки, администратору — вся история URL, включая результаты TOML.
Проверка владельца одинакова для нового маршрута и прежнего `/api/ads`,
который сохранён для совместимости с клиентами, ожидающими массив.

## Интерфейс и проверки

`web-server/src/pages/` содержит страницы входа, подписок и объявлений;
`components/` — формы, таблицу и выбор дат; `hooks/` — загрузку данных
и управление сессией; `helpers/` — общие преобразования.

Таблица загружает одну страницу и обновляет её каждые 10 секунд после
завершения предыдущего запроса. Смена фильтра или сортировки возвращает
на первую страницу и отменяет старый запрос. Границы календарного периода
рассчитываются в часовом поясе браузера. Ошибка обновления сохраняет уже
показанные результаты, успешное обновление убирает сообщение об ошибке.

Формы блокируются на время отправки. Ошибки валидации показываются текстом;
при HTTP 401 локальная сессия очищается и открывается форма входа.
Выход вызывает `/api/logout`; при сетевой ошибке можно повторить попытку.

```bash
python3 -m pytest -q tests
npm test --prefix web-server
npm run build --prefix web-server
```

Дополнительный браузерный сценарий требует Python-пакет Playwright
и установленный Chromium для Playwright:

```bash
python3 web-server/tests/browser_smoke.py
```

Сценарий использует собранный `web-server/dist`, подменяет все HTTP-ответы
и не обращается к рабочей базе. Проверяет вход/выход, HTTP 401, ошибки
валидации, повторную отправку форм, пагинацию, сортировку и запоздавшие ответы.
Для другого установленного Chromium можно задать `BROWSER_EXECUTABLE`.

Если после переноса `node_modules` с другой ОС сборка падает с `ENOEXEC`,
переустановите зависимости на целевой ОС: бинарники esbuild платформозависимы.
